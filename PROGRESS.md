# PROGRESS.md: where the neural texture / image codec stands (September 8, 2026)

A reference for future sessions: what the codec is, the settings that work (config_a), what was learned on September 7-8, 2026, and what is parked. Every number below comes from a log in the tree; PSNR is Basis Universal's definition (8-bit decoded vs 8-bit source over the original extent), measured by `ntc_decode` on the container unless stated otherwise.

## 1. What exists (tree at the commits after tag `v0.12.3-plain-rounding-default`)

- **Two-level latent + tiny decoder.** Level 0: a full-resolution "selector" plane (1..4 channels), either searched at B bits per texel (`--qat B`) or 8x8 DCT-coded (`--dct-q Q`). Level 1: the "colours" block latent, one 4-channel (or 3) 8-bit sample per NxN texel cell (`--block N`), bilinearly interpolated, 8-bit aware in training (`--qes 0,8`). Decoder: an MLP with inputs = selector + latent channels + cell-local UV (`--pos lv1local`), leaky hidden layers, sigmoid output; 17,17 = 496 weights is the default (see section 3).
- **Training.** Evolution Strategies on the latents (4 pairs) and the MLP (256 pairs, then finite differences from 50%), 8000 iterations, learning rates annealed x1 -> x0.05 over the second half; the quantization switches (DCT snap, 8-bit latent ranges) happen at 50%. GPU (CUDA) and CPU trainers are hand-written mirrors, checked exactly by `--cuda-check` (7 checks incl. the DCT snap and the rate proxy).
- **DCT plane (`[DCT]`, DCT_MVP_PLAN.md, DCT_NOTES.md).** JPEG luma table with libjpeg quality scaling, DC step 4, per-block 4-bit scale code from a decoder-sensitivity probe (refit every 500 iterations, `--dct-refit 500`), plain rounding on every AC by default (`--dct-deadzone 0` since v0.12.3; 1 = the XUASTC dead zone), 1..4 channels with a per-channel q (`--dct-q Q0,Q1`), a rate proxy in the loss (`--dct-lambda L`: integer Exp-Golomb token costs of the perturbed shadow's symbols in the latent ES, plus snap-time truncation; the first-order pair (0,1),(1,0) costs 0.25 of its bits, `--dct-lambda-lo`).
- **Container (`[NTCB]`, NTCB_PLAN.md, NTCB_NOTES.md).** `--write-ntcb` writes `model.ntcb`: bit-packed, no entropy coding (fixed-width indices; DCT tokens as DC / run / magnitude / sign / EOB), fp16 MLP, whole-file hash, 6-bit sync markers that encode kind + level + channel, exact reconciliation against the bit simulator, a self-check that re-reads the file. Both readers (the trainer's `--load` and the standalone SSE4.1 `ntc_decode`) accept it; 27 layouts verified byte-identical. Version 2 (a `dct_flags` byte per DCT level); model file v14.
- **Reporting.** Every run: `--write-ntcb`, then a FRESH `ntc_decode <dir>/model.ntcb -o <dir>/ntcb_decoded --compare <image>`; the quoted PSNR is that decoder's. Rates: **raw** (the file on disk), **order-0** (level 0 tokens + latent indices + MLP under adaptive order-0), **est** (level 0 order-0 + level 1 lossless DPCM (floor((left+up)/2)) residuals order-0 + fp16 MLP: the number a basic real coder reaches), **ctx** (level 0 under an up/left context; a ceiling, not part of est). `target.png`, `recon_q_final.png` and `ntcb_decoded.png` are all at the source size.

## 2. config_a (the settings to use)

```
build_cuda\Release\ntc.exe <image> --cuda --block 6 --latent 0 0 1 --latent2 0 0 4 --filter nearest,bilinear --pos lv1local
  --dct-q Q --dct-refit 500 --qes 0,8 --mlp 17,17 --mlp-pairs 256 --iters 8000 --lr-anneal 0.5 0.05 --mlp-fd 0.5
  --leak 0.0009765625 --dct-map all --lat-init-image --write-ntcb --out out_<image>_b6_dct<Q>_c4_mlp17_lam<L>_init_8k
build\Release\ntc_decode.exe <dir>\model.ntcb -o <dir>\ntcb_decoded --compare <image>
```
- `--block 6` = level 1 at 1/6 (state "1/6" in every result); `--latent2 0 0 4` = 4 latent channels; `--mlp 17,17` = 496 weights (state the count).
- `L = min(0.5, 7.5 * S(q)^2)` with `S = q < 50 ? 50/q : 2 - q/50`: 0.5 up to q ~87, then 0.3 at q 90, 0.075 at q 95, 0 at q 100. Since September 8, 2026 (evening) the trainer applies this recipe by default when `--dct-lambda` is not given (the smallest value over the level-0 channels; the `dct` settings line says "recipe"); `--dct-lambda L` overrides it and 0 turns the term off. The directory token `_lam<L>` still records the effective value. (Higher lambdas damage edge / detail coefficients at low q and low-variance blocks at mid q; PSNR does not show it, the eye does.)
- Plain rounding, `--dct-lambda-lo 0.25`, `--dct-shadow-pull 0.01` and the lambda recipe are the binary's defaults; `--lat-init-image` (level-0 channel 0 starts at the image luma scaled to [-1,1]) and `--dct-shadow-pull 0.01` (each latent step moves the level-0 shadow 1% toward its snapped plane, so coefficients below their quantizer step decay instead of random-walking under Adam; `--dct-shadow-reset` sets the shadow to the plane at each refit and is the weaker form) are part of config_a and must be passed.
- Searched-plane variant: replace `--dct-q Q --dct-refit 500 --dct-map all --dct-lambda L` by `--qat B` (dir `..._qat<B>_...`).
- Directory names: defaults omitted, `8k` = 8000 iterations on the GPU; non-defaults get a token (`_lo0`, `_dz1`, `_seed2`, `_posnone`, `_es`, `_trunc`). Always give the FULL path `C:\dev\neural\out_...`.

## 3. What was learned (September 7-8, 2026)

1. **The container closed the loop.** Every bitrate since is a byte count or a figure a coder reaches; the simulator and the writer reconcile exactly on every layout (NTCB_NOTES.md sections 8-10).
2. **The rate proxy works, through the ES term, not the truncation.** At the recipe lambda it beat lambda 0 on both axes at every q from 15 to 80 on five of six battery images (BATTERY_NOTES.md), e.g. image3 q 50: 45.24 -> 46.28 dB at 0.794 -> 0.663 bpp order-0. Truncation-only barely moves the rate; ES-only carries it. Lambda must be small: 0.5 is the cap (edge coefficients at low q, flat blocks at mid q otherwise).
3. **Plain rounding beats the XUASTC dead zone** on this plane (model16 q 50: 36.85 vs 35.95 dB; q 80: 38.42 vs 37.63; model9 q 95 good basin: 40.47 vs 39.82): the dead zone reconstructs |q| = 1 at 1.5 steps and causes mosquito noise. Default since v0.12.3. The JPEG luma table stays (a conservative psychovisual prior, right for a generic texture / material compressor).
4. **The small decoder regularises the plane.** With 1056 weights the level-0 plane grows a per-block / per-cell structure (the decoder exploits its cell-UV input); with 496 it stays smooth, and an 8x8 DCT codes a smooth plane cheaply (model13 6x6 q 80: 42.26 vs 37.77 dB at less rate). Default 17,17.
5. **Seed variance and the luma start.** The float phase can land in bad basins (model9 4x4 q 95: seeds 35.19 / 39.82 / 35.07; model13 q 80 seed 2: 37.42 vs 42.26), with or without the cell UV. Initialising level-0 channel 0 from the image luma (`--lat-init-image`) fixed every bad seed tried (model13 seed 2 -> 41.34, model9 seeds 1/3 -> 40.03 / 40.30) and makes seeds agree within 0.1 dB. Removing the cell UV also prevents the second-half collapse but costs ~1 dB in a good basin; kept.
6. **Cell size sets the rate; q sets the plane.** model11 q 30 lambda 60: 4x4 38.28 dB @ 1.85, 6x6 37.12 @ 1.02, 8x8 36.48 @ 0.70 bpp order-0 with the plane at 0.19-0.24 throughout. On a photo (image4) 1/8 cells with 3 channels beat 1/6 with 4 on both axes (42.78 @ 1.224 est vs 42.67 @ 1.332).
7. **The block latent is close to white.** Its 8-bit indices carry ~7.6 bits of entropy each on the game textures; DPCM gains only ~8% there (0.82 -> 0.755 bpp on model9), more on a photo (image4: 0.71 -> 0.54). It gets cheaper by training it to be cheaper (a rate term on level 1), not by coding; DCT-coding it is parked (quality risk).
8. **Both level-0 modes ship.** The DCT plane makes single textures usable at decent rates (model13: 42.26 dB @ 1.96 order-0 / 1.78 est; image4: 42.78 @ 1.22 est); searched bits cost more but the errors are per-texel and predictable and win on fine detail (chief1: 1-bit search 31.55 dB @ 1.81 est vs DCT q 50 31.77 @ 2.14; 3-bit 38.53 @ 3.80). PSNR overstates the visual gap (DCT errors are perceptual); PSNR-HVS-M (in basisu) is the metric to port when needed.
9. **The shadow pull (September 8).** Coefficients of the level-0 shadow below their step have zero error gradient, and Adam normalises the noise gradient into fixed-size steps, so they random-walk until they cross the step and appear in the plane at full amplitude: the 'high-frequency wreck' in `latent_008000.png`, and the random strong top-frequency ACs, worst at low q. Pulling the shadow 1% per step toward its snapped plane fixes it: model4 1/4 3-ch q 25 32.16 -> 34.43 dB (1.595 -> 1.686 est), q 50 33.78 -> 36.28 (2.001 -> 2.016), image4 q 20 38.31 -> 39.93, model13 q 80 41.42 -> 43.92 (1.945 -> 1.856), model9 q 95 37.99 -> 38.34; pull 0.02 equals 0.01, 0.05 starts to cost; the reset alone gives half the gain.
10. **Reference points.** BC7 at 8 bpp: bc7f 43.78 dB on model15, bc7e 41.0-45.6. model13 6x6 q 80 lambda 2: 42.26 dB at 1.96 bpp order-0 (a good-basin single seed; luma-init runs give 41.3-41.4).

## 4. Parked / next (post-freeze; his calls)

- Per-block source-variance lambda weight (flat blocks favour MSE over bits) and a source-frequency weight (penalise plane coefficients at frequencies the source block lacks); both held unless periodic planes reappear with the luma start.
- Lossless coder for the latent (DPCM + order-0 arithmetic; est already models it) and the real entropy coder for the container's `coding` byte (order-0 / context on the DCT tokens).
- Trainer robustness beyond the luma start: best-of-N warm start, earlier DCT switch (`--dct-start 0.25` gained 0.13 dB on m1), per-texel central-difference gradient for the plane.
- Multi-spectral decomposition (DCT-coded lower bands) and a rate term on level 1: ideas only.
- PSNR-HVS-M from basisu; per-texture loss kinds for materials; m1.png is a normal map (RGB PSNR understates what matters).
