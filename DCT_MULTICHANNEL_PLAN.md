# DCT_MULTICHANNEL_PLAN.md: lifting the one-channel restriction of the DCT-coded selector plane

Plan written September 7, 2026 by a planning agent, read-only, against the working tree (main.cpp 3713 lines, cuda/ntc_cuda.cu 1042, cuda/ntc_cuda.h 123, ntc_decode.cpp 1225; main.cpp and ntc_decode.cpp were being edited concurrently for `--write-ntcb`, so hook sites are named by the code around them). Goal: `--latent 0 0 C` with `--dct-q` for C = 1..4, each channel its own 8x8 DCT-coded plane with its own per-block 4-bit scale code and its own q. Experimental, off by default, removable; the three hand-written mirrors (main.cpp, cuda/ntc_cuda.cu, ntc_decode.cpp) change together where they change at all.

Queue position: implement after the `--write-ntcb` container is reviewed and tagged (see the NTCB plan). Release procedure: two Fable 5.1 medium reviews, fixes, verification, local commit with an annotated tag.

## 1. `--dct-q` syntax, validation, per-channel q and step tables

**Syntax.** `--dct-q Q` applies Q to every channel; `--dct-q Q0,Q1[,Q2,Q3]` one per channel, exactly the `--qat B1,B2` convention (the `--qat` parser loop that splits on `,` and sets `o.qat_ch.assign(1, -1)` on a malformed token, then `o.qat = max`).

**Options.** Next to `int dct_q = 0;` add `std::vector<int> dct_q_ch;   // [DCT] per level-0 channel (size 1 = every channel)`. Keep `o.dct_q` as the maximum of the list so every existing `o.dct_q > 0` gate (the padding lcm, the `--qes` single-value rule, the layout checks, the banner, `dct_start_it`, the refit schedule, the in-loop switch, the raw-bpp banner loop) stays untouched, the way `o.qat` is the max of `o.qat_ch`.

**Parser.** The `else if (a == "--dct-q") { o.dct_q = atoi(next()); i++; }` line becomes the `--qat`-style loop filling `o.dct_q_ch`, then `o.dct_q = max`.

**Validation** (the `[DCT] option ranges` block, the line `if (o.dct_q < 0 || o.dct_q > 100)`): replace with (a) malformed list -> `--dct-q: malformed quality list (use Q or Q0,Q1,... with Q = 1..100)`; (b) every entry in 0..100, and when the max is > 0 every entry must be >= 1 (`--dct-q: every channel needs 1..100 when the DCT plane is on`); (c) `o.dct_q_ch.size() > 1 && (int)o.dct_q_ch.size() != o.LC` -> `--dct-q lists %zu qualities but level 0 has %d channels` (`o.LC` is known here; the `--qat` check does the same at this point); (d) when the size is 1, `o.dct_q_ch.assign(o.LC, o.dct_q_ch[0])`.

**Layout checks and setup** (the block `if (o.dct_q > 0) { ... }` after the `--qes` resolution): delete the `if (o.LC != 1)` refusal; replace it with `if (o.LC > MAX_DCT_CH) { printf("--dct-q: level 0 may have at most %d channels\n", MAX_DCT_CH); return 1; }` (the CUDA envelope refuses the same). `D.dct.q.assign(o.LC, o.dct_q)` becomes `D.dct.q = o.dct_q_ch`. The `dct_build_steps` loop is already per channel and now builds different tables when the q differ; `dc_step` and `dc_raw_bits` stay shared (one `--dct-dc-step` for the level; a per-channel DC step is not needed and would change the ntcb level record).

**Text that prints `o.dct_q` as `%d`** must switch to the list: the warm-start note in the loader (`the warm start for --dct-q %d`), the raw-bpp banner (`--dct-q %d level 0 (rate from the bit simulator once live)`); use `dct_spec(D.dct)` (already `"50,30"`-capable). The `dct      :` banner already prints `q %s` from `dct_spec`. `usage()`: the `--dct-q` block's "Needs --filter nearest, one channel" becomes "1..4 channels (--latent 0 0 C), Q or Q0,Q1,... per channel". README flag row likewise.

**Load mismatch**: `dct_ok` compares `saved_dct_q == D.dct.q` already, and the message prints ` --dct-q 30,50 --dct-dc-step 4`; the ntcb loader's `saved_dct_q = N.q` is a per-channel list too. Nothing to change; a v13 file with `q = {30,50}` loaded with `--dct-q 30` (expanded to `{30,30}`) is refused, which is right.

## 2. The probe per channel and the refits

`dct_probe_codes` already does the per-channel probe: for block `(bx, by)` and channel `c` it calls `features(px, py, f)` once per position, which fills `f[0..C-1]` with the current decode-buffer values of every level-0 channel at that texel (`sample_latent` nearest copies all `L.C` values), then overwrites only `f[c]` with the five probe points and leaves `f[0..C-1] \ {c}` at their current snapped values (and level 1's bilinear sample and the positional features after them). So channel c's gain is the decoder's sensitivity to channel c with the other channels held where they are: a conditional sensitivity. This is the right MVP definition; say it in the DCT-region comment ("with the other level-0 channels at their current values") and in DCT_NOTES.

**Cost.** 20 `mlp_forward` calls per block per channel: 0.31 decode-equivalents per channel at 1080², i.e. `C x 0.31` per probe; at 512x512 with C = 2, 8192 x 20 = 164k MLP evaluations = 0.63 decodes. With `--dct-refit 500` on 8000 iterations that is the switch + 7 refits + the end-of-run reprobe = 9 probes = `9 x C x 0.31` decode-equivalents per run; still small (the refit's two host decodes dominate on `--cuda`). Print the figure in the banner: `probe: %d MLP evaluations per block and channel (%.2f decode-equivalents per probe for %d channels)`.

**Refits.** `Decoder::dct_refit` compares `nc[i]` against `dct.code[i]` over all `(block, channel)` and replaces the whole vector: per channel already. Add per-channel moved counts to the refit line when C > 1 (`moved >= 1: 6.6% (ch 4.1% / 9.1%)`), by splitting the `d >= 1` count on `i % C`. The switch line's histogram stays the sum over channels, followed by one `dct codes[c]` line per channel (section 4).

No change to the probe's determinism story (host-fitted, copied, compared exactly by check 7).

## 3. Snap, reconstruction and shadow per channel: host and device

**Host.** `dct_snap_level0` / `dct_recon_level0`: `#pragma omp parallel for schedule(static) reduction(+:changed,nclamp)` over blocks with the channel loop inside; blocks x channels are independent (each `(b, c)` touches its own 64 strided texels and its own 64 symbols), so the result is deterministic and no change is needed. `collapse(2)` is not worth it: at 512x512 there are 4096 blocks for 32 threads. The pre-start clamp (`dct_clamp_level0` over `L0.size()`) and the `qes_refresh` hooks (`if (dct.on && !dct.live) dct_clamp_level0(...)`, `if (dct.live) changed += dct_snap_level0(...)`) are channel-agnostic.

**Device.** `k_dct_snap` and `k_dct_recon` launch `BW*BH*C` threads; `dev_dct_recon_block` decodes `b = i / c_dct.C, c = i % c_dct.C` and reads `c_dct_step[c][code[i]]`, matching the host's `[block][channel]` order (`code[b * Q.C + c]`, `symbols(b, c) = sym + (b*C + c)*64`). `DctDesc { live, C, BW, BH, N, dc_step }` carries C. `set_dct` copies `sizeof(int) * 16 * 64 * d.C` into `c_dct_step` (16 KB at C = 4, inside the constant bank) and `dct_n` codes and `dct_n * 64` symbols. `k_dct_clamp0` runs over `n0 = W*H*C`. Nothing to change; the one text edit is the `init` envelope message, already "level 0 must have 1..4 channels (= dct_C)".

**The `d_zq`-only rule.** `k_dct_recon` writes only `d_zq` (the DEPENDENCY comment: "decode copy only, never the shadow"); with C channels it still writes only level 0 of `d_zq`, all channels, since `dev_dct_recon_block` indexes `L0.C`. Keep; check 7's pre-step comparison depends on it.

**Check 7 on a multi-channel file.** `cuda_check` compares `ns = D.dct.sym.size()` symbols, `n0 = D.lat.lv[0].size()` plane values and `nc = D.dct.code.size()` codes, so every channel's plane and symbols are compared already. Add to the PASS line the channel count (`symbols %zu of %zu (%d channels) differ`) so a log shows what was covered; no logic change. Run it with `--dct-q 50,20` as well as `--dct-q 50` so `c_dct_step[1]` differs from `c_dct_step[0]` and a wrong channel index in either mirror would show as symbol differences (with equal q per channel a `[c]` / `[0]` mix-up is invisible to the check).

## 4. Statistics per channel and summed

Today `dct_analyze` walks the channels and sums into one `DctStats` (`nblk = nb` blocks, `nz_mean` over `nbc = nb*C` (block, channel) pairs, `raw_total` etc. over all channels, `S.header = 96 * C`, `S.code_raw = 4 * nb * C`); the `/blk` figures divide by `nb`, so with C channels they are bits per block position summed over channels. `bitrate_stats` folds `raw_total - header`, `h0_total - header`, `ctx_total - header` and `header` into the run's totals: correct for any C, and `s.bpp_ctx_level0` is the context figure of all level-0 channels, the same meaning the per-texel selector levels give it. Keep all of that byte-identical.

**Per-channel view.** Give `dct_analyze` an optional `int only_c = -1` parameter: the channel loop becomes `for (int c = (only_c < 0 ? 0 : only_c); c < (only_c < 0 ? Q.C : only_c + 1); c++)` and `nbc` becomes `nb * (only_c < 0 ? Q.C : 1)`; `S.nblk` stays `nb`; the `allones` / `dconly` loop and the `blk_*` vectors (indexed `b*Q.C + c`, sized `nbc`) need the same filter (size the vectors `nb*Q.C` regardless and only fill the selected channel, so `dct_map_image` keeps working with the full-C stats). With `only_c = -1` and C = 1 every number is unchanged. `dct_print_codes(Q, S, c)` prints `Q.steps(c, k)` for the named channel (`dct codes[c] ...`); the existing call with the summed stats passes channel 0 when C == 1 (unchanged text) and is replaced by one line per channel when C > 1.

**Final block** (`dct_print_stats`, called before `done:` and at every print with `--dct-stats`): keep every existing `dct <keyword>` line as the summed level (unchanged when C == 1), then, only when `Q.C > 1`, per channel `c` a compact block from `dct_analyze(Q, c)`: `dct[c] q %d nz mean %.2f eob0 %.1f%% lnz %.1f codes k0..k15 ... mean_k %.2f | bits raw %.0f h0 %.0f ctx %.0f (/blk %.2f/%.2f/%.2f = %.4f/%.4f/%.4f bpp) | dc range %d..%d hres %.2f | plane rms %.3f clamped%% %.2f`, plus `dct codes[c]` (the per-channel step tables). The per-channel `raw/h0/ctx` sums (with each channel's 96-bit header and code bits) must equal the summed line's totals; state that as a check and verify it once by hand on the 2-channel run. `dct_plane_stats` gains the same `only_c` filter (stride over `i % L0.C == c`) for the per-channel plane rms.

**Switch and refit lines** (`dct_begin`, `dct_refit_now`): the summed histogram stays; when C > 1 follow with `dct codes[c]` per channel and the per-channel moved percentages (section 2).

**Progress line**: the token group `| dct nz .. lnz .. eob0 .. clamp .. bits/blk r/h/c chg sym N zq M` stays the summed level (nz per (block, channel), bits per block position over all channels, churn over all symbols and values); no per-channel tokens on the progress line (it is already long). Document the meaning of `/blk` with C > 1 in the README row.

**`done:` line**: `[dct: raw h0 ctx code raw/ctx bpp; nz/blk eob0%]` summed over channels (already), `dct_spec` prints `30,50`; the 96-bit per-channel header is in `S.header` per channel already.

**ntc_decode** summary: the `level 0` line prints `q %s` (the list) and `nnz / (nblk * C)`; the `dct` line's code histogram is summed; append `per-channel nz` when `dct_C > 1` (`DctReconStats` gains `nnz_c[4]`, `eob0_c[4]`, filled in the existing loop; ~6 lines). The idct line's MAC/texel already divides by `nsamples * C`.

## 6. Files

**v13 `save_model`**: header `int dct_N, dct_dc_step, dct_C` then `dct_C` ints `q[c]`; payload `int16 sym[BH*BW][dct_C][64]` and `uint8 code[BH*BW][dct_C]` written as one `fwrite` each of the in-memory vectors. The in-memory order is block-major with the channel fastest (`symbols(b, c) = sym[(b*C + c)*64]`), which is what the README calls `[BH*BW][dct_C]`; it is not channel-major, and every reader indexes it the same way (`(b * C + c) * 64` in ntc_decode's `dct_recon_level0` via `i = (by*BW + bx)*C + c`). Verified consistent; no change. Loader: `di[2] == hdr[3] && di[2] >= 1 && di[2] <= MAX_DCT_CH`, q in 1..100, `saved_dct_q == D.dct.q`; ntc_decode: `dct_C == LC0 && dct_C >= 1 && dct_C <= 4`, resizes `dct_sym` to `nblk * dct_C * 64`, `dct_code` to `nblk * dct_C`. Both fine.

**ntc_decode reconstruction**: `dct_recon_level0` loops `by, bx, c` with per-channel step tables (`dct_build_steps(m.dct_q[c], ...)`), writes `z[((by*8+y)*W + bx*8+x)*L0.C + c]`. The planar copy (`planes[c][i] = m.z[i*L0.C + c]`) and `ref_features` for `--verify` read the same `m.z`. Nothing to change beyond the summary lines.

**ntcb** (the concurrent edit): the level record carries `C` bytes `bits[c]` (0 for mode 3), `dc_step`, `C` bytes `q[c]`; the mode-3 body is channel-major (`for c: 4-bit codes of every block, then per block DC + tokens`); `ntcb_restore` and `load_ntcb` mirror that loop. Verify once the edit lands: (a) the writer uses `Q.symbols(b, c)` and `Q.code[b*Q.C + c]` (block-major memory) while emitting channel-major bits, and both readers fill the same memory positions; (b) `NtcbLevel.q` is copied from `D.dct.q` (per channel) and the header parser checks each `q[c]`; (c) the `file:` reconciliation (`content_bits == sim_total - side`) holds on the 2-channel run with `side = 96 * C + 64 * C1` (the dct level's per-channel header and level 1's lo/hi), and `ntcb_restore`'s consistency check `Q.C != N.C` refuses a channel-count mismatch; (d) the trainer's loader sets `saved_dct_q = N.q` so the mismatch message prints the list.

## 9. Line counts, risks, removal

**Estimated lines.** main.cpp ~140 (parser 12, validation 8, setup 4, `dct_analyze` / `dct_plane_stats` `only_c` 15, `dct_print_codes` channel argument 6, `dct_print_stats` per-channel block 25, `dct_begin` / `dct_refit_now` / `Decoder::dct_refit` per-channel lines 20, side-by-side 4, banner / notes / usage / check-7 text 15, comments 10); cuda/ntc_cuda.cu 0-4 (comment: "C channels, one thread per (block, channel)"); cuda/ntc_cuda.h 0; ntc_decode.cpp ~12; README ~15 (two rows, the check-7 sentence, the `--dct-q` paragraph's "one channel"); DCT_NOTES.md addendum with every number from program output.

**Risks.**
- *Probe cost and meaning.* Linear in C (`C x 0.31` decode-equivalents per probe) and negligible at 512²; the conditional-sensitivity definition means channel c's code depends on the other channels' current plane, so the refit percentages may stay higher than in the 1-channel runs (each refit moves both planes under each other). If the refits oscillate, refit one channel per refit event (alternate `c = refits % C`) as the first knob; not in this plan's scope.
- *ES on 2M+ values.* `LatentTrainer::step` perturbs every level-0 value at `sigma 0.05` with `lat_pairs 4`; a pixel's `(e+ - e-)` is attributed to its footprint on each level, which at C channels is C level-0 texels perturbed independently, so each texel's estimate carries the other channels' perturbation as noise: the per-value SNR falls roughly as `1/sqrt(C)` on top of the 1-channel case, and at 1024² x 4 channels the plane has 4M ES-trained values against 4 pairs. m1 at 512² x 2 (524k values) is the small case; watch `chg zq` and the per-channel `plane rms` / `nz` for a channel that never leaves the dead zone (the "nz drifting" / flat-channel signature). Knobs that need no code: `--lat-pairs 8`, `--lat-sigma`, `--dct-start 0.25`. The per-texel central-difference gradient (DCT_MVP_PLAN.md 11.1) is the structural fix and is unchanged in priority.
- *Sigma / lr of the latent ES.* One `--lat-sigma` / `--lat-lr` for every level; the plane is in [-1,1] and sigma 0.05 = 1.6 plane units per step; the second channel may settle at a lower amplitude than the first (the decoder can use it as a modifier), where the same sigma is relatively coarser and the dead zone (`|d| < L`) swallows the shadow's motion until it accumulates. Report the per-channel `dc range` and `plane rms`; no new option in this plan.
- *"Search"-style levels vs this.* The multi-channel selector runs in the logs (`c2q31`, `c2q32`, `c3q311`) train level 0 by the exact per-texel search of `--qat` (one channel at a time, `C0 x 2^B` decodes per step), which is what made a second low-bit channel pay off; a DCT level 0 has no search analogue and both channels train by ES through the snapped plane. So the fair comparisons are the same-layout `--latent 0 0 2` float / `--qes 8` runs (to be trained) and the 1-channel DCT run at the same rate, not the `c2q31` points; a DCT plane of channel 1 also cannot be "1 bit": its cost is whatever the simulator charges, so a cheap second channel needs its own low q (`--dct-q 30,5`), which the syntax allows and the sweep should include.
- *Reporting drift.* The per-channel `dct[c]` sums must equal the summed lines; check once by hand (the DCT_NOTES hand-count style) and keep the two loops in `dct_analyze` as one function with the `only_c` filter, not a second copy.
- *Concurrent ntcb edit.* The writer / readers are per channel by design; the checks in section 6 are the only coupling, and they run after both changes are in the tree.

**Removal.** Section 7's list; with it deleted the tree returns to the one-channel MVP (the `o.LC != 1` refusal restored), and the file format, kernels and readers are unchanged either way.
